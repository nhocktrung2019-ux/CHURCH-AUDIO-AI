# CHURCH AUDIO AI — v1.20 to v1.24 Measurement Workflow

## v1.20 — Position tracking
- Room-bounded X/Y/Z measurement points, room and zone identifiers, stable position IDs.
- Rejects non-finite/out-of-room coordinates; supports 3D distance calculations.
- The existing RoomPlanner3D scene is preserved. Registered measurement positions are rendered as distinct markers in the SVG room view and Three.js/WebGL scene; markers are not speaker objects and do not represent SPL magnitude.

## v1.21 — Calibration intelligence
- Records microphone ID/serial, 94 or 114 dB SPL reference, measured level, correction, calibration and expiry dates.
- Rejects expired records and inconsistent correction values (tolerance 0.2 dB).
- User-entered metadata is not a traceable calibration certificate. Verify calibrator, microphone, serial and certificate at the venue.

## v1.22 — Measurement-position 3D overlay
- Registered room/zone/position coordinates are rendered as distinct markers in the existing 2D SVG and Three.js/WebGL room scenes.
- Markers are position references only; they do not imply a measured SPL value or create a heatmap.
- Measured SPL heatmap, interpolation limits, sample-density and calibrated reading overlays remain follow-on work.

## v1.23 — Delay and phase
- Geometric propagation delay uses configurable sound speed (default 343 m/s).
- Phase comparisons require matching session, input device and frequency. Geometric delay is not an acoustic alignment measurement.
- Hardware latency, polarity, crossover, room reflections and impulse-response quality still require onsite verification.

## v1.24 — Reports and DSP safety
- Versioned JSON report preserves position and reading provenance; only measured dB SPL with a present, unexpired calibration record can be accepted as SPL evidence.
- DSP proposal validation limits filters to -12..0 dB, 20 Hz..20 kHz and Q 0.3..12. Validation is not a device-specific DSP export protocol and never writes to hardware.

## Validation and limitations
- Automated tests cover bounds, calibration expiry/consistency, delay math, phase comparability, SPL evidence separation and DSP proposal limits.
- Android debug build must pass CI after these changes. No physical Android test, external calibrator traceability check, LAN DSP control, Windows installer, signed release APK or acoustic certification is implied.
