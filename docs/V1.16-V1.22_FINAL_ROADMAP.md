# CHURCH AUDIO AI — v1.16 to v1.22 Final Delivery Track

**Baseline checked:** `main`, package `0.30.0-beta.1`  
**Purpose:** turn the current beta into a verified Android + Windows church-acoustics product without replacing the existing Three.js church scene.

## Non-negotiable engineering rules

- Preserve `RoomPlanner3D` and `ChurchSceneWebGL`; extend them with stable room, zone, speaker and measurement IDs.
- Separate calibrated measured dB SPL, uncalibrated/manual values, dBFS, simulated coverage and interpolated surfaces in both types and UI.
- Never combine readings across sessions, weighting, time weighting or calibration chains.
- A 3D heatmap must show sample count, spatial coverage and interpolation limits. Do not extrapolate beyond supported measurement coverage.
- Delay from geometry is an estimate only. Absolute alignment requires synchronous channels on a verified shared hardware clock and characterized input/output latency.
- Auto EQ remains cut-only, quality-gated and operator-approved. No automatic DSP writes.
- Never guess manufacturer specifications or network protocols. Keep unknown model revisions explicitly unverified.
- A debug APK is not a signed release; a successful build is not proof of physical measurement accuracy.

## Version sequence

### v1.16 — Zone uniformity calculation foundation
- Add a pure, testable analyzer for calibrated SPL readings grouped by stable zone and measurement-point IDs.
- Energy-average repeated captures at each point, then compare spatial points within each zone and zone-level results.
- Reject dBFS, manual, simulated, interpolated, invalid, expired-calibration and out-of-range values.
- Reject mixed sessions, weighting, time weighting and calibration chains.
- Report accepted/rejected counts, zone coverage, min/max, spread and energy average.
- Keep the existing 3D scene and current manual zone worksheet intact.

**Acceptance:** regression tests cover all provenance and compatibility gates; no unsupported value enters calibrated summaries.

### v1.17 — 3D measured SPL and coverage overlays
- Connect zone and measurement-point IDs to the existing 3D room model.
- Render measured points separately from modeled speaker coverage.
- Add heatmap only when spatial sampling and coverage rules are met; expose interpolation method and unsupported regions.
- Add per-zone measured summary and before/after comparison.

**Acceptance:** dragging/resizing room objects does not corrupt measurement coordinates; saved projects migrate safely; sparse points never create a misleading full-room surface.

### v1.18 — Delay Zone and speaker alignment
- Calculate geometric propagation distance and temperature-adjusted arrival-time estimates for each speaker/zone/reference point.
- Display per-zone advisory delay, reference point and assumptions.
- Add coverage/arrival-time map and exportable technician worksheet.
- Keep measured, estimated and unavailable states distinct.

**Acceptance:** calculation tests cover geometry, temperature, invalid coordinates and non-negative relative delays; no DSP write is issued.

### v1.19 — Equipment library and processing profiles
- Extend verified manufacturer-source records for the requested JBL CBT, Bose MA12/402/802/502, Inter-M CU-series and TOA models.
- Preserve model/revision distinctions; missing tolerance, polar or max-SPL data remains explicitly unknown.
- Add microphone profiles for verified Shure dynamic and gooseneck models.
- Provide conservative Gate/Compressor starting points for microphones and Compressor/Limiter worksheets for speaker chains.

**Acceptance:** every sourced numeric field has manufacturer/source provenance and units; recommendations are advisory, never auto-applied.

### v1.20 — LAN/DSP integration readiness
- Implement model-specific adapters only where public/vendor protocol evidence exists.
- Start with network configuration validation and read-only status/parameter retrieval.
- Add authentication, timeouts, reconnect policy, range validation, read-back and audit trail before any controlled write is considered.
- Maintain manual import/export worksheets for unsupported devices.

**Acceptance:** no generic packet format; unsupported CD48 or other protocol operations remain disabled until vendor evidence and hardware tests exist.

### v1.21 — Bilingual workflow, reports and platform hardening
- Complete Vietnamese/English labels and error/status vocabulary.
- Add guided measurement workflow and optional voice guidance that does not compete with active microphone capture.
- Finalize project backup/restore, CSV/JSON and printable PDF report consistency.
- Validate Android WebView/USB routing and Windows desktop packaging approach.

**Acceptance:** language switching does not alter persisted measurement values; backup/restore round-trips project schema; platform capability limits are visible.

### v1.22 — Final release candidate
- Run full regression suite, TypeScript/Vite build, Android sync and debug/release build.
- Configure permanent Android signing secrets; publish only a signed APK from a reviewed release tag.
- Produce and test a Windows installer/package.
- Verify upgrade, backup/restore, permissions, microphone routing, external USB interface, 3D interaction and performance on real devices.
- Perform calibrated acoustic acceptance: SPL reference comparison, repeatability, RT60 sanity checks, frequency-response/phase alignment where hardware permits, and multi-position zone survey.
- Freeze release notes, known limitations, support instructions and rollback procedure.

**Final exit criteria:** all automated checks green; signed Android artifact and Windows package verified; physical-device and acoustic acceptance evidence recorded; no critical defects; no standards-compliance claim beyond the tested measurement chain.
