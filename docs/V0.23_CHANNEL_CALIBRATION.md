# v0.23 channel calibration foundation

## Implemented in this branch

- Versioned calibration profile (schemaVersion: 1) keyed to the exact interface identity, zero-based input channel, output identity and sample rate.
- Runtime validation rejects malformed objects/points, duplicate or unsorted frequencies, unsupported values, and profiles that do not cover at least 50 Hz–10 kHz or exceed the supported Nyquist margin.
- Magnitude correction uses log-frequency interpolation.
- Phase correction unwraps wrapped phase onto the nearest 360-degree branch before interpolation. The eventual capture workflow must sample densely enough that the real phase change between adjacent calibration points is less than 180 degrees; sparse captures cannot disambiguate hidden wraps.
- Calibration application is fail-closed: it returns null if any requested transfer point is malformed or falls outside the measured calibration band. It never silently labels an uncorrected out-of-band point as corrected.
- Loopback delay is removed separately from phase/magnitude correction.
- Differential Reference/Measurement correction subtracts the measured calibration delta between two input channels of the same interface/output/sample rate. It returns only frequency bins covered by both profiles; no out-of-band bins are passed through.
- Storage helpers isolate profiles by exact device/channel/output/sample-rate identity and reject malformed or mismatched saved JSON.
- TransferFunctionPanel now includes a guided USB loopback task: choose an input channel, select an output, collect PCM via AudioWorklet, enforce sample-quality/coherence gates, require a second matching capture before saving, and export/delete the JSON profile.
- Repeatability gate compares mean magnitude difference (≤0.75 dB), RMS phase difference (≤10°) and loopback delay difference (≤0.15 ms) over at least eight shared frequency points. These are application-level guardrails for rejecting obviously unstable captures, not a published instrument accuracy specification.
- Synchronous Reference/Measurement analysis automatically applies differential channel correction when both exact-identity profiles are available; otherwise the result remains explicitly uncorrected. Shared calibration coverage limits which frequency bins are displayed.
- The current 4096-point estimator requires a sample rate at or below 96 kHz for its lowest analysis bin to cover 50 Hz; the calibration UI rejects higher rates rather than saving a profile with an insufficient low-frequency band.

## Required electrical procedure before saving a profile

1. Use the same USB/OTG audio interface for output and input. The app binds a profile to the selected browser input ID, output ID, channel and sample rate, but browser APIs do not prove that an input/output pair belongs to one physical interface. Verify the interface routing manually before proceeding. Do not calibrate from a Bluetooth input, a different interface, a speaker, a room or an acoustic microphone path.
2. Connect the selected line output to the selected line input using a safe, correctly attenuated electrical loopback cable. Never connect a powered speaker output directly to an interface input.
3. Identify the exact output and the exact zero-based input channel. Repeat calibration for every input channel that will be used for synchronous transfer measurements.
4. Capture a broadband sweep/noise signal without clipping. Record the sample rate, frequency response, wrapped phase, and relative loopback delay. The phase sampling grid must be dense enough to unwrap reliably.
5. Repeat the capture without changing the route or gain. The UI only saves after the second capture matches the first profile identity and passes the configured magnitude/phase/delay repeatability limits. If the comparison fails, it does not save and asks for another capture.

## What these helpers do not prove

- Browser device IDs may change after reconnects, OS permission changes or WebView updates. A saved profile must be selected again or re-captured if exact identity cannot be verified.
- Same AudioWorklet frame clock does not prove independent ADC/DAC hardware clocks are phase-locked.
- A single loopback profile cannot calibrate a loudspeaker, power amplifier, room, acoustic microphone response or acoustic propagation.
- A USB/OTG device may expose different sample rates, channel maps or processing modes on Android. Those require physical validation.
- The guided capture/export/delete workflow and two-capture repeatability gate are connected in TransferFunctionPanel, but neither has yet been run on a physical Android USB/OTG interface. The current branch code does not prove a real hardware profile has been captured.
- Auto EQ remains locked for synchronous mode until captured profiles are confirmed on real Android hardware, channel timing is validated, and results agree with a reference analyser.
